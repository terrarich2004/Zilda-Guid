## 1. Архитектура движка: как всё устроено под капотом

Чтобы уверенно писать моды и не гадать, почему игра ведет себя тем или иным образом, важно понимать границу между C++ ядром и скриптами Lua.

**C++ ядро** берет на себя ресурсоемкие низкоуровневые задачи:

- Хранение сетки вокселей и сжатие чанков алгоритмами RLE и Deflate.
- Построение полигональной сетки чанков (жадный мешинг) и рендеринг через шейдеры OpenGL.
- Просчет базовой физики твердых тел (AABB) и бросание лучей (raycasting).
- Звуковой микшер через OpenAL и сетевой стек (TCP/UDP сокеты, HTTP).

**LuaJIT скрипты** управляют всей игровой логикой. Скрипты компилируются на лету при старте мира. Вы правите файл `.lua` в текстовом редакторе — перезагружаете мир или применяете команду перезагрузки — и код сразу работает.

### 1.1. Кадры (FPS) и Тики (TPS): где что вычисляется

В игре работают два независимых цикла обновления:

- **Кадры отрисовки (Render Frames / FPS)** — частота вывода картинки на экран (60–144+ раз в секунду). В цикле кадра обновляются визуальные эффекты: интерполяция движения скелетов, погодные частицы, покачивание камеры и отрисовка UI.
- **Логические тики (Game Ticks / TPS)** — фиксированная частота симуляции игрового мира. По умолчанию движок работает на **20 TPS** (один логический такт каждые 50 миллисекунд). В тиках тикают таймеры печей, растет пшеница, работает ИИ мобов и проверяются физические зоны.

> ⚠️ **Осторожно с производительностью в тиках**
>
> Никогда не запускайте тяжелые поиски по миру (например, сканирование 10 000 блоков вокруг игрока) в каждом тике. Для периодической логики блоков используйте параметр `tick-interval` (например, раз в 20 тиков = раз в секунду), а для мобов — таймеры задержки между проверками окружения.

### 1.2. Структура каталогов игры

Движок ожидает строго определенную структуру папок на диске:

```text
📁 Zilda/  # Корневая директория игры
    📁 res/  # Системные ассеты движка (шейдеры, шрифты)
    📁 res/content/  # Встроенные системные паки (core, base)
    📁 packs/  # Пользовательские моды и пакеты контента
        📁 my_mod/  # Каталог отдельного пака
            📄 package.json  # Манифест (id, версия, зависимости)
            📄 content.json  # Список зарегистрированных блоков/предметов
            📁 blocks/  # Описания воксельных блоков в JSON
            📁 items/  # Описания предметов инвентаря в JSON
            📁 scripts/  # Скрипты логики на LuaJIT
            📁 textures/  # Текстуры блоков, предметов, UI
    📁 worlds/  # Сохранения миров
        📁 World1/  # Папка конкретного мира
            📄 world.json  # Сид, генератор, метаданные мира
            📁 regions/  # Файлы чанков вокселей (.voxreg)
            📁 data/  # Файлы данных, сохраненные модами
    📄 settings.toml  # Настройки графики, звука и управления
```

## 2. Виртуальная файловая система (VFS) и адресация файлов

В Zilda нет прямых путей вида `C:\Games\Zilda\res\texture.png`. Движок монтирует все папки установленных модов и базовых ресурсов в единое виртуальное дерево.

### 2.1. Пространства имен (Namespaces) и префиксы

Любой ассет (текстура, звук, файл модели, скрипт) адресуется в формате:
`имя_пака:относительный/путь/к/файлу.расширение`

| Синтаксис пути | Где файл ищется на диске | Примечание |
| --- | --- | --- |
| `base:textures/blocks/stone.png` | В папке пака `base` | Прямое обращение к ресурсу конкретного мода. |
| `mymod:scripts/magic.lua` | В папке пака `mymod` | Скрипт из вашего мода. |
| `textures/items/ruby.png` *(без префикса)* | В папке текущего пака | Если вы находитесь внутри файлов пака `mymod`, движок автоматически подставит `mymod:`. |

> 💡 **Совет: Когда префикс обязателен**
>
> Если ваш мод использует текстуру, звук или модель из другого пака (например, из базового `base`), указывать префикс `base:` обязательно. Если забыть префикс — движок будет искать файл внутри вашей папки и выдаст ошибку отсутствия ресурса (например, покажет фиолетово-черный куб вместо блока).

### 2.2. Приоритеты источников и переопределение файлов (Overlay)

Если два разных мода содержат файл с абсолютно одинаковым виртуальным путем (например, `base:textures/blocks/dirt.png`), движок загрузит файл из того пака, который стоит **позже в списке загрузки** (или зависит от первого).

Это позволяет создавать классические ресурс-паки: вы создаете мод, объявляете зависимость от `base`, кладете свои версии текстур по тем же путям — и игра заменяет их без модификации исходных файлов базового пака.

### 2.3. Где и как сохранять данные мода

Для записи пользовательских файлов мода (статистика, кастомные конфиги, сохраненные состояния) в библиотеке `pack` есть две функции:

**Сохранение файлов в мире и глобально**

```lua
-- 1. Файл привязан к конкретному миру:
-- Путь на диске: worlds/<ИмяМира>/data/mymod/player_stats.json
local world_path = pack.data_file(PACK_ID, "player_stats.json")
file.write(world_path, json.tostring({ kills = 42 }))

-- 2. Глобальный файл (один на всю игру, между всеми мирами):
-- Путь на диске: packs/mymod/shared_config.json
local global_path = pack.shared_file(PACK_ID, "shared_config.json")
file.write(global_path, json.tostring({ theme = "dark" }))
```

## 3. Контент-паки (Моды)

Контент-пак — это самостоятельная папка внутри `packs/`. Движок не требует упаковки в zip или jar на этапе разработки: всё работает прямо из обычной папки.

### 3.1. Манифест пака: `package.json`

Файл `package.json` обязан лежать в корне папки каждого мода. По нему движок определяет порядок загрузки и зависимости.

**Пример package.json**

```json
{
  "id": "magic_world",
  "name": "Magic World Mod",
  "version": "1.0.0",
  "author": "Player1",
  "description": "Магические кристаллы, жезлы и големы.",
  "dependencies": [
    "base"
  ],
  "optional-dependencies": [
    "minimap"
  ]
}
```

> ⚠️ **Внимание: Правила для ID мода**
>
> Поле `id` может содержать только строчные латинские буквы (`a-z`), цифры (`0-9`), символы подчеркивания (`_`) и дефисы (`-`). Длина — строго от 2 до 24 символов. Пробелы, заглавные буквы и русские символы ломают адресацию VFS и вызовут ошибку загрузки.

### 3.2. Регистрация контента: `content.json` и `tags.toml`

Просто положить JSON-файл блока в папку недостаточно. Чтобы игра знала, что именно загружать, в корне пака создается `content.json`:

**Пример content.json**

```json
{
  "blocks": [
    "ruby_ore",
    "magic_altar"
  ],
  "items": [
    "ruby_gem",
    "fire_staff"
  ],
  "entities": [
    "stone_golem"
  ],
  "layouts": [
    "altar_gui"
  ]
}
```

Файл `tags.toml` группирует контент по тегам. Это избавляет от хардкода: например, инструмент разрушает любые блоки с тегом `#ores`, даже если эти блоки добавлены другим модом.

**Пример tags.toml**

```toml
[blocks]
ruby_ore = ["ores", "stone_type"]
magic_altar = ["crafting_stations"]

[items]
ruby_gem = ["gems", "magical"]
fire_staff = ["weapons", "magic_tools"]
```

### 3.3. Предварительная загрузка ресурсов: `preload.json`

Если не указать тяжелые ресурсы в предзагрузке, игра начнет парсить 3D-модель и текстуры в тот момент, когда сущность впервые появится в поле зрения. Это вызывает неприятный кратковременный фриз кадра (статтер).

Чтобы всё загрузилось заранее во время экрана загрузки мира, в корень пака кладется `preload.json`:

**Пример preload.json**

```json
{
  "models": [
    "magic_world:golem",
    "magic_world:crystal"
  ],
  "skeletons": [
    "magic_world:golem"
  ],
  "animation": [
    "magic_world:golem_walk"
  ],
  "fonts": [],
  "shaders": []
}
```

### 3.4. Тексты и локализация: папка `texts/`

Файлы локализации именуются по кодам языков: `texts/ru.properties`, `texts/en.properties`:

**texts/ru.properties**

```properties
block.magic_world:ruby_ore.name = Рубиновая руда
item.magic_world:fire_staff.name = Посох Огня
ui.altar.title = Алтарь зачарования
```

В Lua текст извлекается вызовом `gui.str("ui.altar.title")`.

## 4. Воксельные блоки (Blocks)

Мир Zilda разбит на вертикальные чанки размером **16 × 256 × 16 вокселей**.         Каждый воксель в памяти занимает 32 бита: 16 бит отведено под числовой ID типа блока, и 16 бит — под его текущее состояние (state).

### 4.1. Свойства блока в JSON

Описания блоков лежат в папке `blocks/*.json`. Ниже разобран полный пример блока со всеми ключевыми секциями:

**blocks/ruby_ore.json**

```json
{
  "texture": "ruby_ore",
  "model": "block",
  "draw-group": "opaque",
  "obstacle": true,
  "solid": true,
  "breakable": true,
  "selectable": true,
  "picking-item": "magic_world:ruby_ore",
  "material": "stone",
  "emission": [8, 1, 3],
  "light-passing": false,
  "sky-light-passing": false,
  "particles": "magic_world:sparkles",
  "base:durability": 3.5,
  "base:loot": {
    "type": "item",
    "item": "magic_world:ruby_gem",
    "count": [1, 3],
    "tool": "pickaxe",
    "min-tier": 2
  },
  "script-name": "magic_world:blocks/ruby_ore.lua",
  "tick-interval": 20
}
```

#### Внешний вид и геометрия

| Поле JSON | Тип | Назначение |
| --- | --- | --- |
| `texture` | string | Имя PNG-текстуры из папки `textures/blocks/` (без расширения). Применяется ко всем 6 граням куба. |
| `texture-faces` | object | Индивидуальные текстуры граней: `top`, `bottom`, `north`, `south`, `east`, `west` или `side` для боковых. |
| `model` | string | Геометрия: `"block"` (стандартный куб 1x1x1), `"cross"` (крестовой спрайт для цветов и травы), `"custom"` (кастомная 3D-модель) или `"aabb"`. |
| `model-name` | string | Имя файла модели при `model="custom"` (.model / .mdl, OBJ, VEC3). Например: `mymod:torch`. |
| `draw-group` | string | Режим отрисовки: `"opaque"` (цельные глухие блоки, объединяются в единую геометрию), `"translucent"` (полупрозрачные с сортировкой глубины: вода, лед), `"transparent"` (листва, решетки), `"billboard"` (поворот к камере). |
| `material` | string | Звуковой материал (`"stone"`, `"wood"`, `"dirt"`, `"metal"`, `"glass"`). Задает звуки шагов, удара и поломки. |
| `particles` | string | Имя системы частиц, непрерывно испускаемой вокселем в мир (дым из трубы, искры). |

#### Освещение и прозрачность

| Поле JSON | Тип | Назначение |
| --- | --- | --- |
| `emission` | [r, g, b] | Блок сам излучает свет. Три целых числа от 0 до 15. Например: `[15, 12, 4]` — теплый свет факела. |
| `light-passing` | boolean | Пропускает ли блок искусственный свет. Для стекла, воды и листвы — `true`. |
| `sky-light-passing` | boolean | Пропускает ли блок дневной свет солнца сверху. |
| `shadeless` | boolean | Игнорировать динамические тени. Блок всегда отображается на 100% яркости. |
| `culling` | boolean | Отсекать ли невидимые смежные грани при соседстве с глухими блоками (экономит видеопамять). |

#### Физика и взаимодействие

| Поле JSON | Тип | Назначение |
| --- | --- | --- |
| `obstacle` | boolean | Является ли блок твердым физическим препятствием для движения игрока и мобов. |
| `hitbox` | [x1,y1,z1, x2,y2,z2] | Границы коллизии от 0.0 до 1.0. Например, плита в полблока: `[0, 0, 0, 1, 0.5, 1]`. |
| `grounded` | boolean | Требуется ли блоку опора снизу. Если блок под ним сломан — этот блок тоже разрушается (факелы, цветы). |
| `selectable` | boolean | Подсвечивается ли блок контуром при наведении прицела. |
| `replaceable` | boolean | Можно ли установить другой блок прямо на это место, заменив его (вода, трава). |
| `breakable` | boolean | Разрушается ли блок в режиме выживания. |
| `picking-item` | string | Какой предмет попадает в руку при клике средней кнопкой мыши или разрушении. |

#### Инвентарь блока и многоблочные структуры

| Поле JSON | Тип | Назначение |
| --- | --- | --- |
| `inventory-size` | int | Количество ячеек встроенного инвентаря блока. Сохраняется в файл чанка. |
| `ui-layout` | string | Имя XML-макета интерфейса, автоматически открывающегося при клике ПКМ (сундук, печь). |
| `size` | [w, h, d] | Многоблочные структуры. Например, колонна 1x3x1: `"size": [1, 3, 1]` автоматически занимает 3 вокселя по высоте. |
| `rotation` | string | Профиль вращения: `"none"` (фиксирован), `"pane"` (4 стороны света), `"pipe"` (все 6 направлений оси). |

### 4.2. Как устроено 16-битное состояние блока (State)

В каждом вокселе 16 бит зарезервировано под его состояние:

- **Биты 0..2 (3 бита)** — индекс поворота блока (0..7 вариантов ориентации).
- **Биты 3..5 (3 бита)** — индекс сегмента для многоблочных структур с `size > 1`.
- **Биты 6..15 (10 бит)** — свободное пространство для ваших собственных полей через секцию `"fields"`!

**Объявление битовых полей в JSON**

```json
"fields": {
  "is_open": { "bits": 1, "offset": 6 },
  "signal_level": { "bits": 4, "offset": 7 }
}
```

В скрипте чтение и запись происходят прозрачно:

**Чтение и запись полей в Lua**

```lua
local open = block.get_field(x, y, z, "is_open") == 1
block.set_field(x, y, z, "is_open", open and 0 or 1)
```

## 5. Предметы и Инвентарь (Items)

Предметы описываются в JSON-файлах каталога `items/`. В отличие от блоков, предметы существуют только в инвентарях игроков, сундуках или в руках персонажа.

### 5.1. Конфигурация предмета в JSON

**items/fire_staff.json**

```json
{
  "icon-type": "sprite",
  "icon": "magic_world:textures/items/fire_staff.png",
  "model": "magic_world:fire_staff",
  "stack-size": 1,
  "uses": 250,
  "emission": [12, 4, 1],
  "script-name": "magic_world:scripts/items/fire_staff.lua"
}
```

| Поле JSON | Тип | Назначение |
| --- | --- | --- |
| `icon-type` | string | Формат иконки в инвентаре: `"sprite"` (плоская PNG-текстура), `"block"` (автоматический изометрический рендер блока), `"model"` (произвольная 3D-модель) или `"none"`. |
| `icon` | string | Путь к файлу текстуры (например `"textures/items/gem.png"` или `"blocks:dirt"`). |
| `model` | string | Имя 3D-модели (.model / .mdl, OBJ, VEC3), отображаемой в руках персонажа от первого и третьего лица. |
| `stack-size` | int | Максимальное число предметов в одной ячейке (по умолчанию 64). Для оружия, инструментов и брони обычно указывают 1. |
| `uses` | int | Счетчик прочности (число использований). При вызове `inventory.use()` из Lua значение уменьшается. При достижении нуля предмет разрушается. |
| `emission` | [r, g, b] | Свечение предмета в руках игрока в темноте (0..15 для каждого канала цвета). |
| `placing-block` | string | ID блока, который будет установлен в мир при клике ПКМ (например, для саженцев или факелов). |
| `script-name` | string | Путь к скрипту поведения предмета при атаке, клике ПКМ или использовании. |

### 5.2. Локальные свойства предмета (кастомные NBT-данные в слотах)

В Zilda можно прикрепить к любому конкретному предмету в слоте произвольные данные: уровень заточки, оставшуюся ману, ник владельца, координаты точки привязки компаса.

Данные хранятся прямо в ячейке инвентаря и автоматически сохраняются в файл мира:

**Использование кастомных данных предмета в Lua**

```lua
-- scripts/items/fire_staff.lua
function on_use(player_id)
    local invid, _ = player.get_inventory(player_id)
    local slot = player.get_selected_slot(player_id)

    -- Читаем текущий уровень заряда из NBT-свойств слота
    local charge = inventory.get_data(invid, slot, "charge") or 100

    if charge >= 10 then
        charge = charge - 10
        inventory.set_data(invid, slot, "charge", charge)

        -- Динамически обновляем подсказку в инвентаре
        inventory.set_description(invid, slot, "Заряд: " .. charge .. " / 100")

        -- Тратим 1 единицу прочности самого предмета
        inventory.use(invid, slot)

        -- Воспроизводим звук выстрела
        audio.play_sound("magic_world:sounds/fireball.ogg", "regular", 1.0, 1.0)
    else
        print("Недостаточно заряда для выстрела!")
    end
end
```

> 💡 **Совет: Поведение свойств при разделении стека**
>
> Когда игрок разделяет стек предметов правой кнопкой мыши, прикрепленные данные **не копируются**, а переносятся в новый стек. Это встроенная защита движка от дюпа характеристик при разделении стака.

## 6. Сущности и архитектура ECS (Entities, Components)

Вместо классической иерархии наследования классов в Zilda используется чистая компонентная архитектура (ECS).

**Сущность (Entity)** — это просто целочисленный идентификатор (UID) в мире. У нее нет жестко зашитого поведения. Все свойства и физика задаются набором подключенных **Компонентов (Components)**.

### 6.1. Декларация сущности в JSON

Файлы существ и объектов хранятся в папке `entities/*.json`:

**entities/stone_golem.json**

```json
{
  "hitbox": [0.6, 1.8, 0.6],
  "components": [
    "transform",
    "rigidbody",
    "skeleton",
    "core:pathfinding",
    "core:mob",
    "magic_world:components/golem_ai.lua"
  ],
  "properties": {
    "max_health": 200,
    "speed": 3.0
  }
}
```

### 6.2. Встроенные компоненты движка

| Компонент | За что отвечает | Ключевые методы в Lua |
| --- | --- | --- |
| `transform` | Позиция, ориентация (поворот) и масштаб в 3D пространстве. | `get_pos()`, `set_pos(vec3)`, `get_rot()`, `set_rot(quat)` |
| `rigidbody` | Физика тела: гравитация, отскок от вокселей, скорость перемещения, трение о землю и воздух. | `get_vel()`, `set_vel(vec3)`, `is_grounded()` |
| `skeleton` | Скелет персонажа/моба, кости, привязка воксельных моделей к суставам. | `get_matrix(bone)`, `set_visible(bool)` |
| `core:pathfinding` | Алгоритм поиска пути A* по воксельной сетке с обходом ям, стен и препятствий. | `set_target(vec3)`, `get_route()` |
| `core:mob` | Базовое поведение моба (поиск целей, дальность агро, патрулирование). | Управляет базовым перемещением к цели |
| `core:animator` | Конечный автомат анимаций (переключение между покоем, ходьбой и атакой). | Плавный переход между дорожками анимации |

### 6.3. Написание пользовательских компонентов на Lua

Собственный компонент — это скрипт в папке `scripts/components/`, реализующий стандартные хуки жизненного цикла:

**scripts/components/golem_ai.lua**

```lua
-- scripts/components/golem_ai.lua
local Golem = {}

function Golem:on_create(entity, args)
    self.entity = entity
    self.health = entity:get_property("max_health") or 100
    self.attack_cooldown = 0
end

function Golem:on_update(entity, delta_time)
    if self.attack_cooldown > 0 then
        self.attack_cooldown = self.attack_cooldown - delta_time
    end

    local pos = entity.transform:get_pos()
    local players = player.get_all_in_radius(pos, 16.0)

    if #players > 0 then
        local target_pid = players[1]
        local target_pos = vec3(player.get_pos(target_pid))

        -- Отдаем команду встроенному C++ компоненту поиска пути
        local pf = entity:get_component("core:pathfinding")
        if pf then
            pf.set_target(target_pos)
        end

        -- Если цель на расстоянии удара — наносим урон
        if vec3.distance(pos, target_pos) < 2.0 and self.attack_cooldown <= 0 then
            player.damage(target_pid, 20)
            self.attack_cooldown = 1.5
        end
    end
end

function Golem:on_hurt(entity, attacker_uid, damage)
    self.health = self.health - damage
    if self.health <= 0 then
        entities.despawn(entity:get_uid())
    end
end

return Golem
```

### 6.4. Управление сущностями из скриптов

**Спавн и манипуляции с сущностями**

## 7. Модели, Анимации и Риггинг (.model, .anim, Скелеты)

В Zilda Engine 3D-модели и скелетные анимации описываются в удобных декларативных текстовых файлах. Их легко редактировать в любом блокноте или прямо во встроенном внутриигровом редакторе без тяжелых внешних программ.

### 7.1. Текстовые 3D-модели (.model / .mdl)

Файлы моделей с расширением `.model` или `.mdl` помещаются в папку `models/` контент-пака. Они строят геометрию из легковесных примитивов:

- `@box` — трехмерный параллелепипед (коробка) с возможностью раздельной настройки граней через `@part`, вращением и удалением скрытых граней (`delete`).
- `@rect` — плоский прямоугольник (плащи, знамена, трава, плоские элементы декора).
- `@tri` — произвольный треугольник с нормалями и UV-разверткой.
- `@bone` — узел скелета или группа трансформации (смещение, поворот, масштаб). Именованные кости экспортируются в скелет сущности.

**Пример модели меча со скелетом (models/sword.model)**

```model
# Модель меча в формате .model / .mdl
@bone name 'hilt' {
    @box from (-0.1, -0.2, -0.05) to (0.1, 0.0, 0.05) texture "magic_world:gold"
    @box from (-0.25, 0.0, -0.06) to (0.25, 0.08, 0.06) texture "magic_world:gold"
    
    @bone name 'blade' move (0.0, 0.08, 0.0) {
        @box from (-0.08, 0.0, -0.02) to (0.08, 0.9, 0.02) texture "magic_world:steel"
        @tri a (0.0, 1.15, 0.0) b (-0.08, 0.9, 0.0) c (0.08, 0.9, 0.0) texture "magic_world:steel"
    }
}
```

### 7.2. Спецификация анимаций (.anim)

Файлы с расширением `.anim` управляют трансформациями костей сущностей или свойствами камеры во времени. Каждая директива отвечает за конкретный канал (`x`, `y`, `z` для перемещения, поворота или масштабирования).

**Пример анимации взмаха мечом (animations/sword_slash.anim)**

```anim
# Анимация удара в формате .anim
@configure fps 30 duration 0.5 rotation-order XYZ

@rotate bone arm_right by x curve linear {
    @key frame 0 value 0
    @key frame 5 value -60
    @key frame 10 value 75
    @key frame 15 value 0
}

@move bone blade by y curve bezier {
    @key frame 0 value 0 lx -2 ly 0 rx 2 ry 0.1
    @key frame 10 value 0.1 lx 8 ly 0.1 rx 12 ry 0
    @key frame 15 value 0 lx 13 ly 0 rx 15 ry 0
}
```

#### Процедурные математические формулы

Для циклических и естественных движений (дыхание, походка, покачивание деревьев, взмах крыльев) вместо расстановки десятков ключевых кадров можно использовать аналитические формулы через атрибут `func`:

**Процедурная синусоида в .anim**

```anim
# Процедурная анимация покачивания хвоста
@rotate bone tail by y func (sin(t * 4.0) * 15.0)
@move bone body by y func (sin(t * 2.0) * 0.03)
```

### 7.3. Управление анимациями и моделями в Lua

**Загрузка и воспроизведение в Lua**

```lua
-- Динамическая загрузка модели из скрипта
assets.parse_model("model", model_text, "custom_sword")

-- Динамическая загрузка анимации
assets.parse_animation("anim", anim_text, "sword_slash")

-- Запуск анимации на скелете сущности
animation.play("magic_world:sword_slash", entity.skeleton)

-- Асинхронное действие (корутина)
animation.action(function()
    time.sleep(0.5)
    print("Взмах завершен!")
end)
```

## 8. Генератор мира (World Generation)

Генератор отвечает за процедурное создание бесконечного мира при перемещении игрока по воксельной карте.

### 8.1. Пайплайн генерации чанка

1. **Карта высот (Heightmap)**: вычисление базового рельефа местности с помощью шумов.
2. **Выбор биома**: определение климата (пустыня, лес, горы, тундра) на основе шумов температуры и влажности.
3. **Наслоение вокселей**: укладка камня, земли, песка или снега в зависимости от высоты и биома.
4. **Прорезка пещер**: вычитание вокселей 3D-шумом внутри монолита камня.
5. **Спавн руд**: генерация жил полезных ископаемых по высотным поясам.
6. **Декорации и структуры**: расстановка деревьев, цветов и запеченных фрагментов построек (`.vox`).

### 8.2. Библиотека карт высот: `Heightmap`

Карта высот представляет собой двумерную матрицу 16×16 чисел для одного чанка:

Симплекс-шум (плавные горы и равнины)

Ячеистый шум Вороного (границы биомов)

| Метод Heightmap | Назначение |
| --- | --- |
| `hm:noise(seed, octaves, freq, persistence)` | Заполняет карту сглаженным симплекс-шумом для генерации холмов. |
| `hm:cellnoise(seed, freq)` | Ячеистый шум Вороного (идеален для формирования четких зон биомов). |
| `hm:crop(x, y, w, h)` | Обрезает карту высот до указанного прямоугольника. |
| `hm:resize(new_w, new_h)` | Масштабирует карту высот с бикубической интерполяцией. |
| `hm:at(x, z)` | Возвращает точную высоту в воксельной точке чанка. |
| `hm1 + hm2`, `hm1 * hm2` | Попиксельное сложение и умножение карт (наложение мелкой ряби на большие горы). |

### 8.3. Пример генератора чанков с рудой

**generators/custom_world.lua**

```lua
-- generators/custom_world.lua
local generator = {}

function generator.init(seed)
    print("Генератор запущен с сидом: " .. seed)
end

function generator.generate_chunk(chunk_x, chunk_z)
    local hm = Heightmap.new(16, 16)

    -- Накладываем шум Перлина (сид, октавы=4, частота=0.01)
    hm:noise(world.get_seed(), 4, 0.01, 0.5)

    -- Масштабируем шум [0..1] в диапазон высот мира [40..90]
    hm:map(40, 90)

    local STONE = block.index("base:stone")
    local DIRT = block.index("base:dirt")
    local GRASS = block.index("base:grass_block")
    local RUBY_ORE = block.index("magic_world:ruby_ore")

    for x = 0, 15 do
        for z = 0, 15 do
            local height = math.floor(hm:at(x, z))
            for y = 0, 255 do
                local wx = chunk_x * 16 + x
                local wz = chunk_z * 16 + z

                if y == 0 then
                    block.set(wx, y, wz, STONE, 0)
                elseif y < height - 3 then
                    -- Генерация рудной жилы глубже 45 блока с шансом 1.5%
                    local is_ruby = (y < 45) and (math.random() < 0.015)
                    block.set(wx, y, wz, is_ruby and RUBY_ORE or STONE, 0)
                elseif y < height then
                    block.set(wx, y, wz, DIRT, 0)
                elseif y == height then
                    block.set(wx, y, wz, GRASS, 0)
                end
            end
        end
    end
end

return generator
```

### 8.4. Структуры и фрагменты (`.vox`)

Готовые постройки (деревья, дома, башни) сохраняются в бинарные фрагменты `.vox`.         При генерации фрагмент размещается в мире одной строкой:

**Размещение фрагмента структуры**

```lua
local hut = VoxelFragment.load("magic_world:structures/witch_hut.vox")
-- Вставляем структуру в чанк на высоту 70 с поворотом на 90 градусов
hut:place(chunk_x * 16 + 4, 70, chunk_z * 16 + 4, 1)
```

## 9. Звуковая подсистема (Audio)

Вывод звука в Zilda реализован через библиотеку OpenAL (бекенд `ALAudio`). Если у пользователя отключен звук в `settings.toml` (параметр `[audio] enabled=false`) или не найдено аудиоустройство, движок переключается на безопасную заглушку `NoAudio`.

### 9.1. Каналы звука и спикеры

Любой воспроизводимый звук управляется через **Спикер (Speaker)** — временный контроллер с числовым ID. Спикер автоматически уничтожается после завершения воспроизведения или вызова `audio.stop()`.

| Звуковой канал | Назначение | Поведение при паузе игры |
| --- | --- | --- |
| `master` | Глобальная громкость всех звуков. | Не используется для прямого воспроизведения |
| `regular` | Звуки мира: шаги, удары блоков, мобы, выстрелы, взрывы. | Ставятся на паузу вместе с миром |
| `ambient` | Фоновые звуки природы: ветер, шум листвы, дождь. | Ставятся на паузу |
| `ui` | Интерфейсные звуки: щелчки кнопок, перетаскивание предметов. | Продолжают звучать на паузе |
| `music` | Фоновая музыка и саундтрек. | Продолжает звучать на паузе |

### 9.2. Разница между `play_sound` и `play_stream`

> ⚠️ **Внимание: Типичная ошибка: запуск музыки через play_sound**
>
> Функция `audio.play_sound()` разжимает аудиофайл **полностью в оперативную память** как несжатый PCM-массив. Для коротких звуков шагов или выстрелов (0.1–2 секунды) это дает мгновенный отклик. Но если вызвать ее на пятиминутном OGG-треке, игра попытается выделить десятки мегабайт памяти в один момент, вызвав зависание кадра.
> Длинные треки и музыку всегда запускайте через `audio.play_stream()`: поток декодирует файл небольшими буферами прямо с диска по мере проигрывания.

### 9.3. Примеры работы с аудио в Lua

**Управление аудио в скриптах**

```lua
-- 1. Короткий 3D-звук в мире (привязан к координатам x, y, z)
local speaker = audio.play_sound(
    "magic_world:sounds/explosion.ogg",  -- путь к аудиофайлу
    "regular",                           -- канал (мир)
    1.0,                                 -- громкость (0.0 .. 1.0)
    1.0,                                 -- скорость / питч (pitch)
    vec3(120, 65, 80)                    -- позиция источника
)

-- 2. Фоновая музыка (потоковое чтение с диска без забивания RAM!)
local music_speaker = audio.play_stream(
    "magic_world:sounds/ambient.ogg",
    "music",
    0.7,
    true                                 -- зацикливание (loop)
)

-- 3. Управление громкостью и остановка
audio.set_volume(speaker, 0.5)
audio.stop(music_speaker) -- спикер удаляется сразу после вызова stop
```

## 10. Система частиц (Particles)

Частицы используются для дыма, огня, капель воды и эффектов магии. Рендеринг тысяч частиц оптимизирован на уровне шейдеров через GPU-инстансинг.

### 10.1. Конфигурация эффекта в JSON

Файлы частиц хранятся в `particles/*.json`:

**particles/sparkles.json**

```json
{
  "texture": "magic_world:textures/particles/spark.png",
  "lifetime": [0.5, 1.2],
  "size": [0.1, 0.3],
  "color-start": [1.0, 0.8, 0.2, 1.0],
  "color-end": [1.0, 0.1, 0.0, 0.0],
  "velocity": [0.0, 2.0, 0.0],
  "spread": [0.5, 0.5, 0.5],
  "gravity": -0.5,
  "collision": true
}
```

| Параметр JSON | Тип | Назначение |
| --- | --- | --- |
| `texture` | string | Имя текстуры частицы в атласе. |
| `lifetime` | [min, max] | Случайный диапазон времени жизни частицы в секундах. |
| `size` | [min, max] | Размер частицы в воксельных единицах. |
| `color-start` | [r, g, b, a] | Цвет и прозрачность частицы при спавне. |
| `color-end` | [r, g, b, a] | Цвет и прозрачность перед исчезновением (плавное растворение). |
| `velocity` | [vx, vy, vz] | Базовый вектор начальной скорости. |
| `spread` | [sx, sy, sz] | Случайный разброс направления вылета. |
| `gravity` | number | Влияние гравитации (отрицательная тянет частицу вверх как теплый дым). |
| `collision` | boolean | Отскакивают ли частицы от твердых блоков при столкновении. |

## 11. Пользовательский интерфейс (XML Layouts, Lua UI)

Интерфейс строится по классической схеме: **декларативная XML-разметка** в `layouts/*.xml` определяет структуру кнопок и панелей, а **Lua-скрипт** управляет их поведением.

### 11.1. Элементы XML-разметки

| Тег | Назначение | Основные атрибуты |
| --- | --- | --- |
| `container` | Невидимый блок для группировки других элементов. | `size`, `align`, `valign`, `spacing`, `margin` |
| `panel` | Видимая панель с фоном и отступами. | `color`, `border-color`, `padding`, `size` |
| `button` | Интерактивная кнопка. | `text`, `color`, `on_click`, `size` |
| `label` | Текстовая метка. | `text`, `font`, `color`, `align` |
| `textbox` | Поле текстового ввода с клавиатуры. | `placeholder`, `max-length` |
| `trackbar` | Ползунок числового значения (громкость, чувствительность). | `min`, `max`, `step`, `value` |
| `checkbox` | Флажок (вкл/выкл). | `checked`, `text` |
| `slot` | Ячейка инвентаря для отображения и перемещения предметов. | `inv` (ID инвентаря), `slot` (индекс ячейки) |
| `slots-grid` | Сетка ячеек инвентаря. | `inv`, `cols`, `rows`, `start-slot` |

### 11.2. Пример верстки окна

## 12. Графика, Погода, Пост-эффекты и 3D Текст

### 12.1. Погода (`gfx.weather`)

Движок поддерживает четыре базовых режима погоды с плавным переходом осадков и освещения: `"clear"` (ясно), `"rain"` (дождь), `"snow"` (снег) и `"storm"` (гроза).

### 12.2. Экранные пост-эффекты (`gfx.posteffects`)

Шейдерные фильтры, накладываемые поверх готового кадра: блюр, подводное искажение, виньетка, ночное видение. Интенсивность эффекта регулируется от 0.0 до 1.0.

### 12.3. Парящий 3D-текст (`gfx.text3d`)

Используется для всплывающего урона над мобами, имен игроков и маркеров объектов в мире.

**Пример работы с эффектами и 3D-текстом**

```lua
-- Плавный переход к грозе за 4 секунды
gfx.weather.change("storm", 4.0)

-- Включение экранного пост-эффекта
local slot = gfx.posteffects.index("base:night_vision")
gfx.posteffects.set_intensity(slot, 1.0)

-- Парящая 3D-надпись над блоком алтаря
gfx.text3d.add(
    "§e[Древний Алтарь]",
    vec3(100.5, 66.2, 100.5),
    16.0 -- дистанция видимости в вокселях
)
```

### 12.4. Цветовые коды форматирования текста

В любых строках (чат, имена предметов, подсказки UI, 3D-текст) работают стандартные коды форматирования со знаком параграфа `§`:

| Код | Стиль / Цвет | Пример |
| --- | --- | --- |
| `§0 .. §9` | Базовые цвета (черный, синий, зеленый, красный, золотой, серый...) | `§cОпасность!` (красный) |
| `§a .. §f` | Светлые цвета (зеленый лайм, циан, желтый, белый...) | `§eРедкий предмет` (желтый) |
| `§l` | **Жирный текст** | `§lВнимание` |
| `§o` | *Курсивный текст* | `§oЗаметка` |
| `§r` | Сброс всех цветов и стилей к обычному | `§cКрасный §rОбычный` |

## 13. События движка (Engine Events)

Движок оповещает скрипты о происходящих в игре событиях через фиксированные функции обратного вызова (хуки).

### 13.1. Основные события

| Событие / Функция | Где объявляется | Когда вызывается |
| --- | --- | --- |
| `on_block_placed` | `scripts/world.lua` | Игрок поставил блок в мир. |
| `on_block_broken` | `scripts/world.lua` | Игрок разрушил блок. |
| `on_block_interacted` | Скрипт блока | Игрок нажал ПКМ по вокселю. |
| `on_block_update` | Скрипт блока | Периодический тик блока (задается через `tick-interval`). |
| `on_neighbor_update` | Скрипт блока | Соседний воксель изменился (поставлен или разрушен). |
| `on_use` | Скрипт предмета | Игрок кликнул ЛКМ или ПКМ с предметом в руке. |
| `on_world_open` | `scripts/world.lua` | Мир завершил загрузку и готов к игре. |
| `on_world_tick` | `scripts/world.lua` | Каждый логический шаг (20 TPS). |
| `on_player_join` | `scripts/world.lua` | Игрок зашел в мир. |
| `on_player_death` | `scripts/world.lua` | Игрок погиб. |

### 13.2. Пользовательская шина событий (`events.*`)

Для общения между разными скриптами или отдельными модами используется глобальная шина:

**Пример работы с событиями в Lua**

```lua
-- scripts/world.lua
function on_world_open()
    print("Мир загружен, скрипты инициализированы.")
end

function on_world_tick()
    -- Вызывается 20 раз в секунду
end

function on_block_placed(player_id, x, y, z, block_id)
    print("Игрок " .. player_id .. " установил блок " .. block_id)
end

function on_block_broken(player_id, x, y, z, block_id)
    print("Блок разрушен на координатах: " .. x .. ", " .. y .. ", " .. z)
end

function on_player_join(player_id)
    local name = player.get_name(player_id)
    print("Игрок подключился: " .. name)
end

-- Регистрация пользовательского события
events.listen("magic:teleport", function(data)
    print("Телепортация на: " .. data.x .. ", " .. data.y .. ", " .. data.z)
end)

-- Отправка события из любого другого скрипта:
events.emit("magic:teleport", { x = 100, y = 64, z = 100 })
```

## 16. Бинарные форматы и спецификации (Specs)

Спецификации для тех, кто пишет внешние инструменты: конвертеры вокселей в Blender, парсеры сохранений миров или сетевые утилиты.

### 16.1. Binary JSON (BJSON v1.1)

Компактный бинарный формат обмена данными Little-Endian. Числа записываются фиксированной длиной без текстового оверхеда.

| Код (байт) | Тип | Формат полезной нагрузки |
| --- | --- | --- |
| `0x00` | null | 0 байт |
| `0x01` | false | 0 байт (значение закодировано в самом типе) |
| `0x02` | true | 0 байт (значение закодировано в самом типе) |
| `0x03` | int8 | 1 байт со знаком (-128 .. 127) |
| `0x04` | uint8 | 1 байт без знака (0 .. 255) |
| `0x05` | int16 | 2 байта со знаком (Little-Endian) |
| `0x06` | uint16 | 2 байта без знака (Little-Endian) |
| `0x07` | int32 | 4 байта со знаком |
| `0x08` | uint32 | 4 байта без знака |
| `0x09` | int64 | 8 байт со знаком |
| `0x0A` | uint64 | 8 байт без знака |
| `0x0B` | float32 | 4 байта (IEEE 754 float) |
| `0x0C` | float64 | 8 байт (IEEE 754 double) |
| `0x0D` | string | uint32 длина + сырые байты UTF-8 |
| `0x0E` | array | uint32 длина + элементы |
| `0x0F` | map / object | uint32 число пар + [ключ string, значение] |

### 16.2. Файл региона чанков (`.voxreg` / v3)

**Структура файла региона .voxreg**

```text
Заголовок (10 байт):
  - Сигнатура (8 байт): '.VOXREG\0' (0x2E, 0x56, 0x4F, 0x58, 0x52, 0x45, 0x47, 0x00)
  - Версия (uint8): 0x03
  - Сжатие (uint8): 0x01 (Deflate)

Таблица смещений:
  - Массив uint32 смещений чанков от начала файла для мгновенного произвольного доступа.

Сжатые чанки:
  - Размер сжатых данных (uint32 LE)
  - Исходный размер распакованного чанка (uint32 LE)
  - Сжатые байты чанка (Deflate)
```

### 16.3. Воксельный чанк (Voxels Chunk v2)

Распакованный чанк 16×256×16 содержит ровно **65,536 вокселей**. Данные разбиты на два раздельных массива для максимальной эффективности RLE сжатия:

- `65536 * 2 байта (128 КБ)` — непрерывный массив 16-битных целых чисел ID блоков.
- `65536 * 2 байта (128 КБ)` — непрерывный массив 16-битных целых чисел состояний (states).

### 16.4. Битовая маска 16-битного стейта вокселя

**Раскладка битов состояния блока**

```text
Биты:   [15 14 13 12 11 10 09 08 07 06 05 04 03 02 01 00]
          |____________________________| |______| |______|
              Пользовательские поля      Сегменты  Вращение
                   (fields)               (size)  (rotation)
  
  Биты 0..2 (3 бита) — ориентация поворота (0..7)
  Биты 3..5 (3 бита) — сегмент блока при size > 1
  Биты 6..15 (10 бит) — свободные пользовательские поля (open, power, etc.)
```

### 16.5. Фрагменты структур (`.vox`)

Файлы запеченных структур представляют собой BJSON документ:

**Схема структуры .vox**

```json
{
  "version": 1,
  "size": [16, 24, 16],
  "block-names": [
    "base:air",
    "base:stone",
    "base:wood_planks"
  ],
  "voxels": [ 0, 0, 1, 1, 2, ... ] // индексы из палитры block-names
}
```

### 16.6. Сетевой протокол удаленной отладки VC-DBG v1.1

Позволяет подключаться к игре внешним отладчиком (например, из VS Code) по TCP сокету:

**Протокол VC-DBG**

```text
1. Рукопожатие: клиент шлет заголовок: 'v' 'c' '-' 'd' 'b' 'g' 0x00 0x01
2. Сервер подтверждает версию.
3. Команды в формате JSON:
   - "connect" — авторизация сессии
   - "set_breakpoint" — установка брейкпоинта на файл и строку
   - "continue", "step_in", "step_over" — управление шагом исполнения
   - "get_variables" — инспекция значений локальных и глобальных переменных
```

## 18. Решение типичных проблем (FAQ)

### 18.1. Черно-фиолетовый куб вместо текстуры блока

> ⚠️ **Внимание: Причина: движок не нашел PNG-текстуру по указанному пути**
>
> 1. **Папка**: текстура блока обязана лежать строго в `textures/blocks/`.
> 2. **Расширение**: в JSON блока свойство `texture` пишется **без .png** (например: `"texture": "crystal_ore"`).
> 3. **Регистр букв**: VFS чувствительна к регистру. `My_Ore.png` и `my_ore.png` — разные файлы.
> 4. **Префикс**: если вы берете текстуру из другого пака, обязательно пишите префикс: `base:textures/blocks/stone.png`.

### 18.2. Скрипт не вызывается

- **Проверьте имя функции**: имена системных хуков строго фиксированы (`on_interact`, `on_block_placed`, `on_update`). При опечатке движок просто не найдет функцию.
- **Проверьте `content.json`**: если блок или предмет не зарегистрирован в массиве `content.json`, движок вообще проигнорирует этот файл.
- **Проверьте консоль**: если в коде Lua была синтаксическая ошибка, игра выведет строку ошибки в консоль или лог `latest.log`.

### 18.3. Игра падает при загрузке мира

- **Ошибка в JSON**: лишняя запятая перед закрывающей фигурной скобкой `}` или пропущенная кавычка ломает парсер.
- **Недопустимый ID в `package.json`**: пробелы, заглавные буквы и русские символы в `id` запрещены.

### 18.4. Горячая перезагрузка без перезапуска игры

Скрипты и макеты интерфейса можно править прямо во время игры. Для обновления конфигурации контента выполните команду `app.reconfig_packs()` в консоли.
